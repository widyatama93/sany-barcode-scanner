# SANY Warehouse & Distribution

This branch builds on scanner commit `9b308812e69d593b7fad0bddae24a1e496e8e3ac`. The scanner remains in `index.html` with its existing html5-qrcode camera flow, DO batch entry, duplicate checks, local draft/history, photo handling, 30-second statistics refresh, and Apps Script form POST.

## Features on this branch

- Single-page navigation for Dashboard, Barcode Scanner, Delivery Pending Monitoring, and QR Monitoring Card.
- Monitoring dashboard metrics, status bars, delayed count, recent activity, and data refresh time.
- Monitoring search, status filter, add/edit form, status validation, aging, and last-updated fields.
- A stable Monitoring ID is generated by Apps Script. QR links contain only that ID and open a live card.
- Google Apps Script module in `Monitoring.gs`, intended to be merged into the existing deployed scanner project.

## Connect the monitoring backend

The Apps Script project behind the existing `SCRIPT_URL` is not included in this repository. The frontend sends `getMonitoring` and `saveMonitoring` actions to that same Web App. Existing deployments will not recognize those actions until the module is added and the Web App is redeployed.

1. Add `Monitoring.gs` to the existing Apps Script project.
2. Run `setupMonitoringSheet_()` once from the Apps Script editor and approve the requested Sheets access. This creates a `Monitoring` tab with its header row.
3. Set the Script Property `SANY_MONITORING_EDITORS` to the comma-separated Google account emails allowed to add or edit monitoring rows.
4. In the existing `doPost(e)`, after parsing the current `payload`, add the following dispatch before the existing scanner-action handling:

   ```javascript
   if (["getMonitoring", "saveMonitoring"].includes(payload.action)) {
     return monitoringResponseOutput_(handleMonitoringRequest_(payload));
   }
   ```

   Keep the current `getStats`, `submitBatch`, and `submitScan` routes unchanged. The scanner sends its JSON inside the form field `payload`; use the parsing already present in the deployed `doPost`.
5. Deploy a new version of the existing Web App. Configure execution and access to match the organization's sign-in policy; editor checks use `Session.getActiveUser().getEmail()`. Test with an allowed editor and a read-only user.

The module uses a 7-day threshold for the dashboard's delayed count: an unshipped record is marked delayed after more than seven days. Change `isDelayed` in `getMonitoringRecords_()` if operations uses a different threshold.

## Run the frontend

Serve `index.html` from GitHub Pages or another HTTPS static host. HTTPS is required by browser camera access. Configure GitHub Pages to publish the branch after the Apps Script route is deployed. Camera access cannot be tested through static code inspection.
